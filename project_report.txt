==============================================================
 PROJECT REPORT
 Business & Service Management System
 Veda Technology Python Internship - Project (Day 3 of 4)
==============================================================

1. INTRODUCTION
A console application in Python that manages the operations of a
technology and digital-services company: customers, services,
training/internship programs, customer inquiries and service
requests. Only public / synthetic data is used; no private Veda
Technology production data is connected.

2. OBJECTIVE
Apply functions, modules, classes, dictionaries, lists, file
handling, validation and basic reporting in a realistic
technology-business scenario.

3. TOOLS USED
Python 3 (standard library only), VS Code, JSON, Git, GitHub.

4. MODULES
main.py              Menu-driven console interface (17 options)
models.py            Customer, Service, Program, Inquiry,
                     ServiceRequest classes + all validators
storage.py           JSON storage: atomic save, backup of bad
                     files, ID counters that are never reused
customer_manager.py  Customer operations and history
service_manager.py   Service operations and status flow
program_manager.py   Programs, seats, enrolment / withdrawal
inquiry_manager.py   Inquiries and service requests
search_manager.py    Search and filtering (all record types)
report_manager.py    Business reports and text-file export
export_manager.py    CSV export and dated JSON backups
test_search_reports.py  Tests for search, filtering, reports
test_core_rules.py   Tests for business rules, storage, export

6. SEARCH & FILTERING
- Keyword search (case-insensitive, every word must match); it also
  matches related names, e.g. "aarav" finds his inquiries.
- Customers : type, city
- Services  : category, status, minimum / maximum price
- Programs  : type, status (including Full), free seats only
- Inquiries : status, priority, topic, customer
- Requests  : status, customer, service, overdue only
- Every filter value is validated; mistakes give a clear message.

7. BUSINESS REPORTS
Overview, services (demand and value), programs (seat utilisation
and fee income), inquiries (by status/priority, open list, average
days to resolve), service requests (earned vs pipeline value,
overdue) and top customers. Can be saved as business_report_<date>.txt.
Money uses Decimal, so totals are exact.

8. BUSINESS RULES AND VALIDATION
- Unique customer e-mails, service names and program names
- No double enrolment; no enrolment in a full or closed program
- Status changes follow fixed flows (e.g. a Completed request
  cannot be reopened); completed programs are frozen
- Records that are in use cannot be deleted
- Only Active services can be requested
- Strict validators for names, e-mail, phone, dates, amounts

9. EXPORT AND BACKUP (DAY 3)
- CSV export: one file per record type in exports/<date>/,
  readable in Excel / Google Sheets (UTF-8 with BOM, lists flattened,
  formula-injection protection for text starting with = or @).
- Backup: dated copy of business_data.json in backups/.

10. TESTING
32 automatic unit tests (python -m unittest) cover:
- customers: e-mail validation and uniqueness, ID reuse, delete rules
- services: unique names, status flow, retired services frozen
- programs: double / full / closed enrolment, seat limits, delete rules
- inquiries and requests: status flows, resolved/completed dates,
  default quote and due date, active-service rule
- storage: save/load round trip, damaged file kept as .corrupt,
  broken references skipped with a message
- search, filters, reports (money totals), CSV export and backup
Menu flows were also tested by hand.

Bug found and fixed during testing: creating a service request
and pressing Enter for the quote (use service price) failed
because the Decimal price was rejected by the money validator.
Fixed in inquiry_manager.py by passing the price as text.

11. CHALLENGES AND LEARNINGS
- Keeping UI, business rules and storage in separate modules made
  new features (search, reports) easy to add without touching
  existing logic.
- Validating data both on input and on file load keeps the data safe.
- Using Decimal for money avoids rounding errors.
- Writing tests quickly exposed a real bug.

12. FUTURE SCOPE
CSV import, user login roles, charts, and a web interface
(Flask or Streamlit).

13. CONCLUSION
The project meets all deliverables and shows practical use of
core Python concepts in a business scenario.
