7. DAY 4 - NEW IN DETAIL
CSV import (menu option 18)
- Imports customers, services or programs from a CSV file.
- Header names are not case-sensitive; extra columns (such as the
  id column of an exported file) are ignored; a UTF-8 BOM is fine.
- Each row uses the same validation and business rules as the
  menu. A bad row is skipped with its row number and reason; the
  good rows are still imported. Importing a file twice is safe
  because every row is then a duplicate.
- Limits: at most 1000 rows per file; clear messages for a missing
  file, empty file, missing columns or a file that is not CSV.
- Files written by the CSV export can be imported again.
Command-line options
- python main.py --report | --export | --backup | --data FILE
- Makes the program usable in scripts without the menu.

8. SEARCH, REPORTS, EXPORT (SUMMARY)
- Search: keyword (case-insensitive, all words must match, also
  matches related names) and filters for every record type.
- Report: overview, services, programs, inquiries, requests and
  top customers; money calculated with Decimal.
- Export: one CSV per record type, formula-injection protection.

9. BUSINESS RULES AND VALIDATION
- Unique customer e-mails, service names and program names
- No double enrolment; no enrolment in a full / closed program
- Fixed status flows; completed program and retired service frozen
- Only Active services can be requested; due date not before
  request date
- Records in use cannot be deleted
- Strict validators for names, e-mail, phone, dates, amounts, IDs

12. CHALLENGES AND LEARNINGS
- Separate modules let new features (search, reports, export,
  import) be added without changing existing logic.
- Validating on input and on file load keeps the data safe.
- Row-by-row import with clear reasons is friendlier than
  rejecting a whole file.
- Early tests found a real bug before submission.
